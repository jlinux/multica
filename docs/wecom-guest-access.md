# 企业微信免账号接入与群会话隔离

此功能复用现有企业微信连接、智能体、聊天会话和任务队列。默认仍要求绑定 Multica 账号；管理员显式配置后，指定群中的无账号用户才能直接向指定机器人提问。无需新建一套智能体服务，也不会为访客创建 Multica 账号。

## 管理员配置

新安装的机器人默认持久化为访客访问关闭。工作区 owner/admin 在 **设置 → 企业微信 → 访客访问** 中管理授权：

1. 打开 "允许无账号用户访问"。
2. 从已有群记录中选择授权群，或手动添加准确的群 ID；没有记录的群需要手动添加，不支持所有群通配授权。
3. 按需开启 "允许无账号用户私聊"，默认建议关闭。开启后，所有能够私聊此机器人的未绑定身份都在授权范围内。
4. 确认只读的执行身份并保存。执行身份固定为当前智能体所有者，且必须仍属于该工作区；普通成员所有者也可以承担此身份，无需提升为 owner/admin。

普通成员只能查看机器人列表中的访客访问状态和授权群数量，不能查看完整授权详情或修改配置；即使拥有该智能体，也不能自行开启访客访问。配置授权者与执行身份是两个概念，保存不会修改成员角色。运行端必须在线才能执行运行，配置页面不会自动启动或更换运行端。

保存成功后立即用于后续授权检查，无需重启后端或重新连接企业微信；多副本读取同一数据库中的配置。加载失败不能视作默认关闭；保存失败或并发修改冲突时，应核对错误、重新加载当前配置并确认保存结果。

这是管理员对所选智能体能力的明确委托。访客不获得登录后台的账号或 token；运行会记录委托用户及 `wecom_guest_grant` 来源，真实企业微信 sender、群、bot 和授权快照保存在会话配置及运行投递快照中。被移出工作区的已绑定用户不会自动降级为访客绕过成员检查。

## 旧环境配置兼容

`MULTICA_WECOM_GUEST_ACCESS` 仅用于兼容升级前已存在、仍有效且尚无数据库访客配置的安装。界面会展示其有效的旧授权；首次保存后，数据库配置成为该机器人的唯一有效配置。数据库中只要存在访客配置，即使明确关闭、为 null 或格式错误，也不会回退到环境变量放行。**数据库接管后，修改或清空环境变量不能撤销数据库中的授权。**

新安装、重装或更换机器人均默认关闭访客访问，需要管理员在界面中显式授权，不能靠遗留环境变量重新放行。同一机器人轮换凭据保留配置。首次保存与旧环境授权完全等价的配置会保留授权指纹和已有访客上下文；后续相同配置保存也不会重置上下文。

以下示例仅供维护尚未接管的旧安装或核对旧版本回滚配置。自托管 Compose 已透传该变量，在 `.env` 中用单引号包住 JSON 数组：

```dotenv
MULTICA_WECOM_GUEST_ACCESS='[{"bot_id":"YOUR_BOT_ID","workspace_id":"11111111-1111-1111-1111-111111111111","agent_id":"22222222-2222-2222-2222-222222222222","sponsor_user_id":"33333333-3333-3333-3333-333333333333","allowed_group_ids":["YOUR_GROUP_ID"],"allow_direct_messages":false}]'
```

上述 UUID 和群 ID 均是示例，必须替换为真实值。每个 bot 最多一条配置。

| 字段 | 含义 |
| --- | --- |
| `bot_id` | 企业微信智能机器人 ID，必须匹配当前安装 |
| `workspace_id` / `agent_id` | 仅授权此工作区的此智能体 |
| `sponsor_user_id` | 运行的执行身份；必须是智能体所有者且仍属于该工作区，可以是普通成员 |
| `allowed_group_ids` | 允许免账号访问的精确群 ID 列表；不支持通配符，群内所有能发消息的人都可使用 |
| `allow_direct_messages` | 是否允许未绑定用户私聊此 bot；开启后，所有能私聊此 bot 的未绑定身份均在授权范围内 |

仅对上述尚无数据库配置的旧安装，修改变量后需重建所有后端副本使其生效；空值或 `[]` 关闭其环境授权。环境配置格式错误、安装与授权不匹配、执行身份退出工作区或不再拥有智能体时，访客运行拒绝执行。

发布配置界面前，先更新所有后端副本。回滚到仅支持环境变量授权的旧版本时，旧后端不会读取数据库配置，必须先核对并同步收紧或关闭所有副本的环境授权，避免恢复已经撤销的群或私聊访问范围。

## 对话行为

- 同一 bot、同一群中的不同发送人使用不同会话；A 的消息、追问、`/new`、`/clear` 不进入 B 的上下文。
- 同一人在同一群的连续消息属于同一对话；不同话题用 `/new` 新建。此版本不自动把同一人的多条并行问题划成多个工单。
- 群消息仍需按现有规则 @ 机器人。回复发回原群；**群内其他人仍能看见回复**，会话隔离不等于私密回复。
- 新版本不会续接旧的多人共享群上下文。历史任务的原群回复地址保留。
- 访客与已绑定账号使用不同会话；实际改变授权会轮换授权代次（`generation`），新消息切换访客会话，防止复用旧授权下的上下文。相同配置保存及等价的首次环境配置接管不会切断上下文。
- 访客不能使用平台直接创建任务的 `/issue` 命令。用自然语言描述问题，由管理员配置的客服智能体判断是否通过其工具创建开发任务。
- 私聊账号用户的路由保持原有行为；访客私聊单独隔离并默认关闭。

## 运行执行和撤销

在消息接入、运行入队、运行领取执行前检查当前有效授权。撤销时，工作区 owner/admin 应在 "设置 → 企业微信 → 访客访问" 中关闭总开关并保存，确认保存成功；收紧范围则移除授权群或关闭私聊后保存。实际变更会轮换授权代次，旧授权下尚未启动的运行（包括重试）会被拒绝，重新启用也不会恢复这些旧运行。已经启动的运行不会自动中止，需要管理员取消。智能体所有权或其工作区成员身份变化也会使原授权失效，不自动转交给新所有者，需管理员重新确认并保存。

访客运行不附加 Multica 个人 connected-app MCP overlay。**这不是运行环境沙箱，也不会收紧智能体已配置的工具、运行机器的文件/网络/SSH/数据库权限、已有登录凭证或 Multica 运行时 API 权限。** 管理员应给客服使用的智能体和运行时配置适当的只读生产访问权限及有限的任务创建权限。流程由提示词约束，真实操作权限由运行环境和工具账号限制。

## 验收

1. 新安装保持默认关闭：未绑定用户仍收到绑定提示；普通成员只看到状态，不能修改授权。
2. owner/admin 在界面中授权测试群并保存：两个无账号用户分别 @ bot，交错追问；各自上下文独立，均回复原群。
3. A 执行 `/new`、`/clear`，B 继续追问，B 上下文不变。
4. 未允许的群和默认关闭的私聊不能免账号使用；已绑定成员保持正常。确认普通成员智能体所有者可以作为执行身份，但不能修改授权。
5. 对兼容旧安装，确认有效环境授权原样展示；首次等价保存后上下文延续。再在界面关闭并保存，确认数据库关闭压过仍启用的环境变量，无需重启或重新连接。
6. 在运行领取前通过界面关闭或改变授权，确认旧授权下排队和重试运行不能执行；重新启用后发起新消息，旧运行仍不能恢复。已开始的运行需单独取消。
7. 检查真实 sender 元数据与委托来源；验证机器人文本和附件均回复真实群 ID。

本变更不新增数据库 migration。现有 `feat/goals` 部署的 migration 编号与仓库不一致，应在单独的部署核对中处理，不能以“本变更无 migration”为由直接运行整套仓库迁移。
