# 企业微信免账号接入与群会话隔离

此功能复用现有企业微信连接、agent、聊天会话和任务队列。默认仍要求绑定 Multica 账号；管理员显式配置后，指定群中的无账号用户才能直接向指定机器人提问。无需新建一套 agent 服务，也不会为访客创建 Multica 账号。

## 管理员配置

后端环境变量 `MULTICA_WECOM_GUEST_ACCESS` 为 JSON 数组。自托管 Compose 已透传该变量。在 `.env` 中用单引号包住整段 JSON，例如：

```dotenv
MULTICA_WECOM_GUEST_ACCESS='[{"bot_id":"YOUR_BOT_ID","workspace_id":"11111111-1111-1111-1111-111111111111","agent_id":"22222222-2222-2222-2222-222222222222","sponsor_user_id":"33333333-3333-3333-3333-333333333333","allowed_group_ids":["YOUR_GROUP_ID"],"allow_direct_messages":false}]'
```

上述 UUID 和群 ID 均是示例，必须替换为真实值。每个 bot 最多一条配置。

| 字段 | 含义 |
| --- | --- |
| `bot_id` | 企业微信智能机器人 ID，必须匹配当前安装 |
| `workspace_id` / `agent_id` | 仅授权此工作空间的此 agent |
| `sponsor_user_id` | 访客任务的执行身份；必须是 agent 所有者且仍属于该工作空间，可以是普通成员，无需提升为 owner/admin |
| `allowed_group_ids` | 允许免账号访问的精确群 ID 列表；不支持 `*`，群内所有能发消息的人都可使用 |
| `allow_direct_messages` | 是否也允许无账号用户私聊此 bot；默认建议 `false`。开启后，所有能私聊此 bot 的外部身份均在授权范围内 |

修改后重建后端容器，使环境变量生效；多副本必须同步更新。配置格式错误、安装与授权不匹配、执行身份退出工作空间或不再拥有 agent 时，访客任务拒绝执行。空值或 `[]` 关闭免账号访问，已有绑定账号的成员仍沿用原权限检查。

只有能够管理后端服务器配置的管理员可以通过此变量授权；普通成员不能通过聊天或自行提交 `sponsor_user_id` 开启访客访问。配置授权者与任务执行身份是两个概念：此配置不修改任何成员角色，也不提升 agent 所有者的工作空间权限。

这是管理员对所选 agent 能力的明确委托。访客不获得登录后台的账号或 token；任务执行会记录委托用户及 `wecom_guest_grant` 来源，真实企业微信 sender、群、bot 和授权快照保存在会话配置及任务投递快照中。被移出工作空间的已绑定用户不会自动降级为访客绕过成员检查。

## 对话行为

- 同一 bot、同一群中的不同发送人使用不同会话；A 的消息、追问、`/new`、`/clear` 不进入 B 的上下文。
- 同一人在同一群的连续消息属于同一对话；不同话题用 `/new` 新建。此版本不自动把同一人的多条并行问题划成多个工单。
- 群消息仍需按现有规则 @ 机器人。回复发回原群；**群内其他人仍能看见回复**，会话隔离不等于私密回复。
- 新版本不会续接旧的多人共享群上下文。历史任务的原群回复地址保留。
- 访客与已绑定账号使用不同会话；授权配置变更也会切换访客会话，防止复用旧授权下的上下文。
- 访客不能使用平台直接创建 issue 的 `/issue` 命令。用自然语言描述问题，由管理员配置的客服 agent 判断是否通过其工具创建开发 issue。
- 私聊账号用户的路由保持原有行为；访客私聊单独隔离并默认关闭。

## 任务执行和撤销

在消息接入、任务入队、任务领取执行前检查授权。清空或修改配置并重建所有后端后，旧授权下尚未启动的任务（包括重试任务）会被拒绝；已经启动的运行不会被环境配置自动中止，需要管理员取消。

访客任务不附加 Multica 个人 connected-app MCP overlay。**这不是运行环境沙箱，也不会收紧 agent 已配置的工具、运行机器的文件/网络/SSH/数据库权限、已有登录凭证或 Multica 运行时 API 权限。** 管理员应给客服使用的 agent/runtime 配置适当的只读生产访问权限及有限的 issue 创建权限。流程由提示词约束，真实操作权限由运行环境和工具账号限制。

## 验收

1. 不配置授权：未绑定用户仍收到绑定提示。
2. 配置测试群：两个无账号用户分别 @ bot，交错追问；各自上下文独立，均回复原群。
3. A 执行 `/new`、`/clear`，B 继续追问，B 上下文不变。
4. 未允许的群和默认关闭的私聊不能免账号使用；已绑定成员保持正常。
5. 在任务领取前关闭授权并更新全部后端，排队访客任务不能执行；恢复授权后发起新消息。
6. 检查真实 sender 元数据与委托来源；验证机器人文本和附件均回复真实群 ID。

本变更不新增数据库 migration。现有 `feat/goals` 部署的 migration 编号与仓库不一致，应在单独的部署核对中处理，不能以“本变更无 migration”为由直接运行整套仓库迁移。
