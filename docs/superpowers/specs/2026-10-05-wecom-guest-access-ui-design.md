# 企业微信访客访问配置界面

状态：用户已确认，开始实施（2026-10-05）。

## 目标与方案选择

在现有「设置 → 企业微信」机器人列表中增加「访客访问」入口，让工作空间 owner/admin 管理无 Multica 账号用户的访问范围。复用现有页面、机器人连接、消息路由和任务授权机制，不增加独立管理系统。

推荐将配置保存到现有机器人安装记录的 JSON 配置中，保存后立即生效。相比通过网页修改服务器环境变量，这不需要重启后端，也适合多个工作空间分别管理。独立的新管理页面没有必要。

## 界面

每个已连接机器人显示访客访问状态和已授权群数量。owner/admin 可以打开配置弹窗；普通成员仅查看状态，不显示编辑操作，后台接口仍独立校验权限。

弹窗包括：

- 「允许无账号用户访问」总开关。
- 授权群列表：从该机器人的已有群记录中选择，支持手动添加、移除群 ID；已授权但没有会话记录的群仍显示。仅使用真实群 ID，不把按发送人生成的内部会话键当作群 ID。
- 「允许无账号用户私聊」独立开关，默认关闭。开启时明确说明所有能够私聊该机器人的外部身份都会在授权范围内。
- 只读显示负责执行的 agent 所有者，以及最近保存者和保存时间。不提供任意选择执行身份或提升成员角色的操作。
- 保存和取消。保存失败保留输入并给出错误信息；加载失败不显示成默认关闭，更不能以空配置覆盖已有授权。

群名只有在系统掌握真实群名时才显示；否则显示群 ID，不将会话标题猜作群名。第一版不承诺自动发现尚无记录的未授权群，手动输入 ID 是补充入口。不提供「所有群」通配授权。

页面简短说明：群内仍需 @ 机器人，不同发送人的会话自动隔离，群内成员仍可看见机器人回复。

## 权限与存储

增加按工作空间和 installation ID 定位的配置读取、更新接口。群候选和完整授权详情仅对该工作空间 owner/admin 开放；普通成员机器人列表只返回授权状态及数量。服务端同时校验安装所属工作空间、渠道为企业微信、安装有效、agent 未归档及所有者仍是成员。非管理员即使拥有 agent，也不能修改访客授权。

更新请求只接收总开关、群 ID 列表和私聊开关；机器人、工作空间、agent 和执行身份由服务端从当前安装与 agent 记录确定，禁止客户端指定任意委托人。校验重复、空白、超长群 ID 和通配符，设置请求体与列表大小上限。

在 `channel_installation.config` 中保存独立的访客配置，包含明确的启用状态、授权范围、固定的执行身份、更新人、更新时间和版本。使用局部 JSON 更新和并发版本检查，避免覆盖机器人密钥或覆盖另一位管理员刚保存的修改。相同机器人轮换密钥保留配置；更换机器人不能继承旧机器人的群授权。撤销、重装也不得让旧环境授权意外恢复。

无需新建业务表或数据库迁移。前端类型、响应校验及查询和更新逻辑放在 `packages/core`；界面放在 `packages/views`，Web 和桌面端共享，补充中英文文案。

## 接管现有环境配置

尚未通过界面保存的安装，继续读取 `MULTICA_WECOM_GUEST_ACCESS` 的有效授权，页面直接展示现有配置。因此客服助手当前 4 个群和私聊关闭状态保持不变。

首次保存后，该机器人的数据库配置成为唯一有效配置；显式关闭也属于已保存配置，不能回退到环境变量重新放行。页面不暴露其他机器人的环境授权。首次无变化保存应保留等价授权指纹，避免无故切断已有访客上下文。

## 生效与撤销

消息接入、任务入队和任务领取统一读取当前有效授权，避免部分路径继续仅检查环境变量。保存成功无需重启后端或断开企微连接，多副本从同一数据库读取生效配置。

保留现有快照和授权指纹机制。实际改变授权后，新消息使用新授权上下文，旧授权下未开始的任务和重试拒绝执行；已开始的运行不承诺自动中止。agent 所有权或成员资格变化仍使旧授权失效，不自动转交给新的所有者。

## 验收

- 管理员查看、启用、关闭、添加和移除群、控制私聊；普通成员与跨工作空间请求不能修改授权。
- 不返回机器人密钥，不允许通过更新接口篡改其他安装配置。
- 环境配置原样展示、首次接管、数据库显式关闭压过环境变量、并发保存冲突和相同配置保存。
- 轮换密钥保留配置，更换机器人不继承旧授权。
- 真实 PostgreSQL 测试覆盖普通成员所有者、无账号用户接入、同群多人隔离及撤销后的入队、领取和重试。
- 前端覆盖加载和保存失败、只读成员、群增删、私聊开关、接口返回格式异常与中英文文案；在浏览器中检查实际页面布局和操作。
