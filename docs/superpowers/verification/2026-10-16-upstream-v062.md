## Integration decisions

The merge retains Goals, milestones, issue links, web/desktop navigation, capability detection, Query cache invalidation and workspace deletion cleanup. The WeCom integration retains administrator-managed guest scopes, no-account access, per-sender group sessions, grant generations/revocation, sponsor membership checks, and exclusion of personal connected-app overlays.

The newly shipped French locale now includes Goals, and French/Japanese/Korean include the existing guest-policy UI. Existing upstream translations remain unchanged; coverage enumerates every shipped locale.

A review found a preexisting delegation-management gap: task/cloud machine credentials could administer guest policies using an effective administrator identity. Guest-policy GET/PUT now require a human owner/admin. A real-auth regression reproduced both machine callers expanding the grant before the fix, then verified both are rejected while a human PAT still succeeds. This restriction is limited to policy management; general runtime API permissions are unchanged.

The release's invocation permission gate is evaluated using the resolved guest sponsor. Actual WeCom delivery addresses are recovered from the new immutable task delivery snapshot, covering text, attachments and relay delivery. Synthetic session keys never become transport group IDs. Guest command denials use the upstream locale mechanism.

SQL queries were combined and regenerated with `make sqlc`. The release's inbox unread-summary path and bounded comment previews remain in place. This local integration does not claim a measured production performance improvement; active inbox pagination remains a separate upstream limitation.

## Migration compatibility

All 502 baseline up-migration files retain their SHA-256 digests. Upstream had changed historical `451_agent_task_comment_thread.up.sql` to remove a queue backfill. This merge preserves the fork's executed file byte for byte: an existing ledger skips it, and a fresh empty installation has no queue rows to backfill. An older untested installation that has not applied this migration still needs its own volume/lock assessment before upgrade.

The 18 Goals migrations keep their complete identities (`456_goal` through `473_milestone_proposal_milestone_index`) and existing legacy alias checksums. Upstream migrations sharing numeric prefixes have different complete identities and all execute normally. A regression helper that selected a numeric range was corrected to select the alias-map identities; the production runner already uses complete identities. The new upstream numeric-prefix lint also recognizes only the 18 exact historical Goals/upstream pairs. An unexpected third collision was rejected by an actual Go negative probe; future migrations must use numbers above the maximum across both histories.
